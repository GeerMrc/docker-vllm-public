# Qwen3.6-27B-FP8 基准测试结果

> 硬件: 4× RTX 3090 24GB (TP=2 per service)
> 模型: Qwen3.6-27B-FP8 (bf16 dtype)
> 前提: `expandable_segments:False` (R12 修复后, CUDA Graph 兼容)

---

## 一、推荐配置摘要

| 场景 | 上下文 | KV | MTP | gpu_util | 并发 | Wall 吞吐 | Decode @c=1 |
|------|--------|----|----|----------|------|----------|------------|
| 通用 Agent (生产默认) | 140K | bf16 | n=1 | 0.96 | 1-4 | 68-203 tok/s | 37.6/s |
| 大上下文 Agent | 145K | bf16 | n=1 | 0.97 | 1-4 | 67-204 tok/s | 36.8/s |
| 长上下文 | 152K | bf16 | n=1 | 0.97 | 1-4 | 53-200 tok/s | 24.0/s |
| 中并发加速 | 132K | bf16 | n=2 | 0.96 | 2-3 | 100-110 tok/s | 19.3/s |
| 中并发长上下文 | 145K | bf16 | n=2 | 0.96 | 2-3 | 98-112 tok/s | 34.2/s |
| 长上下文中并发 | 152K | bf16 | n=2 | 0.96 | 1-3 | 76-126 tok/s | 24.7/s |
| 编码场景 (bf16+MTP) | 140K | bf16 | n=1 | 0.96 | 1-4 | 68-203 tok/s | 37.6/s |

> agent-fast / agent-thinking 生产配置: bf16 KV + 140K + MTP n=1 + gpu_util=0.96 (KV 并发 1.26x, prefill 上限 142,874 tok)
> 标准 Agent 推荐 140K: 可用上下文 ~132K (8K sys prompt 后), decode 37.6 tok/s, c=4 吞吐 203 tok/s
> 长上下文 (152K) decode 降至 24 tok/s, 仅当确实需要 >145K 输入时使用
> code profile (bf16+MTP n=1): decode 37.6/s, c=4 203 tok/s, 可用上下文 ~132K, 适合编码和工具调用
> 长上下文编码 (>145K): 使用 test-spec profile 调整 max_model_len=200704 + n=0 + gpu=0.97, decode 19.9/s, c=4 130 tok/s, 完整 196K 上下文

> **关键发现**: 140K 和 145K 是最佳平衡点 — decode >36 tok/s (vs 152K 的 24 tok/s), c=4 吞吐 >200 tok/s

> 136K c=4 Wall 异常高 (216.4), 可能为测量波动, 其余指标与其他长度趋势一致

> 修复后 decode 吞吐回退 ~20-27%，但 prefill 从不可用变为正常，净收益极大

### R18 bf16+n=0 vs R16 bf16+n=1 (code 基线 vs Agent 默认)

| 指标 | R16 140K n=1 | R18 196K n=0 | 变化 |
|------|-------------|-------------|------|
| max_model_len | 143,360 | 200,704 | +40.0% |
| Prefill 上限 | 142,874 | 200,704 | +40.4% |
| KV 并发度 | 1.31x | 1.04x | -0.27x |
| c=1 Wall | 68.4 tok/s | 23.3 tok/s | -65.9% |
| c=4 Wall | 202.8 tok/s | 130.5 tok/s | -35.7% |
| c=1 Decode | 37.6/s | 19.9/s | -47.1% |
| c=4 Decode | 25.2/s | 31.7/s | +25.8% |
| 视觉编码器 | ✓ | ✓ | 相同 |

> **MTP 影响量化**: n=1 → n=0, c=1 Wall 下降 65.9%, decode 下降 47.1%。MTP n=1 是单请求吞吐的关键加速器。
> **并发补偿**: 无 MTP 时 decode 随并发提升 (c=1: 19.9/s → c=4: 31.7/s), c=4 decode 反超 MTP n=1 的 25.2/s。
> **上下文优势**: 196K 比 140K 多 40% 可用上下文, 适合需要更长代码上下文的编码场景。
> **bf16 绝对上限**: 209,328 tokens (vLLM 启动校验), 超出需切 fp8 KV cache。

## 四、部署决策矩阵

基于 R13-R18 实测数据，为不同场景提供上下文长度与配置选择依据。

### 场景推荐

| 场景 | 推荐上下文 | MTP | KV | Profile | 理由 |
|------|-----------|-----|-----|---------|------|
| 轻量 Agent (2-4K sys prompt) | 132K | n=1 | bf16 | agent-fast | decode 34.8/s, KV 余量充足, 生产验证最充分 |
| 标准 Agent (5-8K sys prompt + 工具) | 140K | n=1 | bf16 | agent-fast | decode 37.6/s, 可用上下文 ~132K, c=4 达 203 tok/s |
| 大上下文 Agent (8K+ sys prompt) | 145K | n=1 | bf16 | test-spec (调整 148480) | decode 36.8/s, 可用上下文 ~137K, c=4 达 204 tok/s |
| 最大上下文需求 (>145K) | 152K | n=1 | bf16 | test-spec (调整 155648) | decode 24.0/s (显著下降), 可用上下文 ~144K |
| 高并发中上下文 (c=2-3) | 145K | n=2 | bf16 | test-spec (调整 148480, n=2) | c=2 98/s, c=3 112/s, decode 34.2/s |
| 高并发长上下文 (c=2-3) | 152K | n=2 | bf16 | test-spec (调整 155648, n=2) | c=2 120/s, c=3 126/s, 但 c=4 退化至 82/s |
| 编码+工具调用 (标准) | 140K | n=1 | bf16 | code | decode 37.6/s, c=4 203 tok/s, 可用上下文 ~132K |
| 长上下文编码 (>145K) | 196K | 无 | bf16 | test-spec (调整 200704, n=0, gpu=0.97) | 完整 196K 可用, c=4 decode 31.7/s |
| 长上下文编码 (fp8) | 256K | 无 | fp8 | test-spec (调整 262144, kv=fp8, n=0) | fp8 牺牲精度换取 256K, 需验证精度 (未测试) |

### 性能-上下文权衡 (n=1)

| 指标 | 132K | 136K | 140K | 145K | 152K |
|------|------|------|------|------|------|
| max_model_len | 135,168 | 139,264 | 143,360 | 148,480 | 155,648 |
| Prefill 上限 | 134,736 | 138,758 | 142,874 | 147,934 | 155,137 |
| c=1 Decode (tok/s) | 34.8 | 36.4 | **37.6** | 36.8 | 24.0 |
| c=4 Wall (tok/s) | 167.7 | 216.4 | 202.8 | 203.8 | 200.3 |
| 8K sys prompt 后可用 | ~124K | ~128K | ~132K | ~137K | ~144K |
| KV 并发度 | 1.43x | 1.35x | 1.31x | 1.27x | 1.21x |

### 决策规则

1. **优先选 140K-145K**: decode >36 tok/s 且可用上下文 >130K, c=4 吞吐 >200 tok/s
2. **避免 152K 除非必要**: decode 从 36→24 tok/s 下降 33%, 仅当输入确实超过 145K 时才值得
3. **n=2 仅用于 c=2-3**: n=2 c=4 一致性退化至 ~80 tok/s, 严禁 n=2 + c=4 组合
4. **132K 生产默认**: 已通过长期生产验证, KV 余量最大, 适合 sys prompt <4K 的场景
5. **编码场景默认 code profile (140K bf16+MTP n=1)**: decode 37.6/s, c=4 203 tok/s, 可用上下文 ~132K, 质量 100%
6. **编码长上下文 (>145K)**: 用 test-spec 调整 max_model_len=200704 + n=0 + gpu=0.97, 完整 196K 可用, decode 19.9/s
7. **bf16 绝对上限 209K**: 超过需切 fp8 KV cache (需先完成 fp8 质量验证), 210K/256K bf16 均启动 OOM
